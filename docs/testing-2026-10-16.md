## Service setup and remaining acceptance

- Supabase settings/JWKS/admin-key requests succeeded. The project advertises ES256 signing keys. Actual application startup reported ready, and anonymous requests to private bootstrap/resume/chat/jobs/search-ticket APIs returned 401. Public configuration exposed only enabled/URL/publishable-key fields.
- Google is **disabled** in the Supabase project. Configure its provider and allowed callbacks before testing real Google sign-in/refresh/logout/account switching.
- Email authentication is enabled, but SMTP/domain setup and actual external email delivery remain pending. No email was sent.
- The production CA certificate file is absent. Local PostgreSQL currently uses encrypted `require` mode; production `verify-full` configuration remains pending.
- Operator invitations remain for the user to manage. No real address was added by the test pass.
- Real provider Auth identity deletion was not exercised on a human account. Fictional local/PostgreSQL deletion and retry handling passed.
- Abrupt OS process death, multi-process worker ownership/timing stress, the full cross-account route matrix, and 15-user embedding/browser/provider resource capacity still require broader acceptance. The passed tests cover representative paths, not every possible race.
- Discovery relevance/coverage and robust live follow-ups need fixes and a reviewed rerun before P4 acceptance. Hosting/deployment remain P5A decisions.
